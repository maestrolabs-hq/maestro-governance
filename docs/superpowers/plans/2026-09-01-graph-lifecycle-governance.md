# Graph Lifecycle Governance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Govern the graph lifecycle hook rollout with an amended gate-versus-lifecycle decision, one immutable central hook revision pinned exactly once in every governed repository (including `.github`), auditable install and required-context evidence, current post-merge blob pins, and a final zero-drift fleet audit.

**Architecture:** `dot-github` publishes the two lifecycle hook definitions. Each governed repository owns one `.pre-commit-config.yaml` that pins the same immutable `dot-github` commit and installs `post-commit` and `pre-push` in addition to the existing quality-gate stages. `maestro-governance` keeps the existing `repo`, `rule`, and scoped `file` directive grammar: pure invariants validate exact hook-pin coverage, while GitHub readers verify effective required contexts and tracked file blobs. The baseline remote desired-repository set remains separate from the workspace-local membership list generated by `maestro-manifests`.

**Tech Stack:** Rust 2024, existing dependency-free `maestro-governance` crate, `gh`, `git`, `prek`, YAML hook configuration, GitHub reusable workflows and rulesets.

**Spec:** `../maestro-core/docs/superpowers/specs/2026-09-01-workspace-intelligence-facades.md` (Approved)

## Global Constraints

- Complete and merge `maestro-project-documentation` governance onboarding from its approved vitrine plan before this plan starts. `baseline.txt`, the remote repository, required contexts, tracked files, and `governance plan` must already cover that lane; onboarding is an explicit prerequisite, not part of lifecycle rollout.
- Amend ADR-0002 before publishing or rolling out lifecycle hooks. Quality hooks remain fast-tier mirrors; lifecycle hooks are durable notifications and never mergeability evidence.
- Do not weaken, remove, rename, or reclassify an existing quality gate. Required context names change only together with their repository ruleset configuration.
- The `post-commit` hook warns after a bounded enqueue failure. The `pre-push` lifecycle hook blocks only when durable scheduling cannot be recorded. Neither hook waits for indexing, parsing, embedding, merging, or synchronization.
- Publish hook definitions once in `dot-github/.pre-commit-hooks.yaml`. Callers contain only the immutable revision and repository-specific arguments.
- Use a full 40-lowercase-hex commit SHA for the `dot-github` `rev`; never a branch, tag, abbreviated SHA, mutable release reference, or local repository entry.
- Keep the existing baseline grammar. Do not add `hook`, `context`, `membership`, or lifecycle directives. Use scoped `file` pins plus pure coverage checks and the existing effective-rules reader.
- Every name parsed from `baseline.repos` must receive exactly one applicable `file .pre-commit-config.yaml <blob> ...` entry. Rollout, evidence, merge, and audit loops derive this set at execution time; they never hard-code a fleet subset. Documentation, manifests, and any later repository are covered whenever they are governed. Overlapping scoped entries and an unscoped-plus-scoped overlap are failures, even when the blobs match.
- `.github` is a governed repository and is the rollout canary. Its repository name is `.github`; its local checkout directory is `dot-github`.
- `baseline.txt` `repo` lines are the remote desired repositories audited through GitHub. They do not discover, authorize, or grant filesystem access to local repositories.
- `.maestro/config/settings.json` `workspace.repositories` is the sole local workspace membership authority. This plan does not edit manifests settings or infer local membership from `baseline.txt`.
- Update every affected `file` blob only from the commit that is actually merged to that repository's default branch. Never pin a working-tree hash or a feature-branch blob and call the fleet current.
- A rollout is incomplete while `governance plan` reports any setting, rule, required-context, file, pin-coverage, or install-evidence drift.
- Installation evidence must follow the reviewed schema published by `dot-github/docs/governance/hook-install-evidence.txt`: exact candidate and configuration digests, installer version, path kind without an absolute path, validation command/result, and one executable/type/generated-byte digest record for each of `pre-commit`, `pre-merge-commit`, `post-commit`, and `pre-push`. Configuration text alone is not installation evidence.
- No synchronous indexing is introduced. Hook tests must use a fake `maestro` executable and fail if it attempts provider/index work before returning.
- Use synthetic paths such as `/somewhere`; do not persist a developer or workspace absolute path.
- Follow strict TDD for executable changes: add the focused test, run it and record the expected RED, implement the minimum GREEN, then rerun the focused test and the repository gate.

## Desired interfaces

Add only these governance interfaces; keep parsing and drift interfaces otherwise unchanged:

```rust
// maestro-governance/src/baseline.rs
pub fn hook_pin_coverage(baseline: &Baseline) -> Vec<HookPinCoverageDrift>;

#[derive(Debug, PartialEq, Eq)]
pub struct HookPinCoverageDrift {
    pub repo: String,
    pub applicable_entries: usize,
}

// maestro-governance/src/github.rs
pub fn read_required_contexts(repo: &str) -> Result<Vec<String>, String>;

// maestro-governance/src/lib.rs
pub const REQUIRED_FAST_CONTEXTS: &[&str];
pub fn required_context_drift(repo: &str, actual: &[String]) -> Vec<String>;
```

`hook_pin_coverage` counts existing `file` entries whose path is `.pre-commit-config.yaml` and whose scope is empty or contains the repository. A repository is clean only when the count is exactly one. `read_required_contexts` reads the effective default-branch pull-request rule through `repos/{org}/{repo}/rules/branches/{branch}` and returns the lexical, deduplicated context names from `required_status_checks`; it does not list or mutate organisation rulesets. `required_context_drift` compares exact names without weakening the set and produces readable missing/unexpected diagnostics.

```bash
  checkout="$(checkout_for "$repo")"

  rg -n "rev: ${HOOK_REV}|maestro-graph-post-commit|maestro-graph-pre-push" \
```

```bash
from hashlib import sha256
from pathlib import Path
import os
import re
import subprocess
import sys

repository, revision, checkout_path, evidence_path = sys.argv[1:]
checkout = Path(checkout_path)
lines = Path(evidence_path).read_text(encoding="utf-8").splitlines()
pairs = [line.split("=", 1) for line in lines]
if any(len(pair) != 2 for pair in pairs):
    raise SystemExit("malformed evidence line")
fields = dict(pairs)
if len(fields) != len(pairs):
    raise SystemExit("duplicate evidence field")
required = {
    "schema", "repository", "candidate_revision", "configuration_sha256",
    "installer", "hooks_path_kind", "validation_command", "validation_exit",
}
for stage in ["pre-commit", "pre-merge-commit", "post-commit", "pre-push"]:
    required |= {
        f"hook.{stage}.executable", f"hook.{stage}.type", f"hook.{stage}.sha256"
    }
if set(fields) != required:
    raise SystemExit("missing or extra evidence field")
if fields["schema"] != "1" or fields["repository"] != repository:
    raise SystemExit("wrong evidence identity")
if fields["candidate_revision"] != revision:
    raise SystemExit("wrong candidate revision")
if fields["hooks_path_kind"] != "git-managed" or fields["validation_exit"] != "0":
    raise SystemExit("installation was not validated")
if fields["configuration_sha256"] != sha256(
    (checkout / ".pre-commit-config.yaml").read_bytes()
).hexdigest():
    raise SystemExit("configuration digest mismatch")
hooks = Path(subprocess.check_output(
    ["git", "rev-parse", "--git-path", "hooks"], cwd=checkout, text=True
).strip())
if not hooks.is_absolute():
    hooks = checkout / hooks
for stage in ["pre-commit", "pre-merge-commit", "post-commit", "pre-push"]:
    if fields[f"hook.{stage}.executable"] != "true":
        raise SystemExit(f"non-executable evidence: {stage}")
    if fields[f"hook.{stage}.type"] != stage:
        raise SystemExit(f"wrong hook type: {stage}")
    data = (hooks / stage).read_bytes()
    if not os.access(hooks / stage, os.X_OK):
        raise SystemExit(f"installed hook is not executable: {stage}")
    if fields[f"hook.{stage}.sha256"] != sha256(data).hexdigest():
        raise SystemExit(f"generated-byte digest mismatch: {stage}")
for name in ["configuration_sha256", *[key for key in fields if key.endswith(".sha256")]]:
    if re.fullmatch(r"[0-9a-f]{64}", fields[name]) is None:
        raise SystemExit(f"invalid digest: {name}")
PY
done
```
